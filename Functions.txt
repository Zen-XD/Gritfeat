Functions are reusable code blocks designed for particular task that are executed when they are called or invoked

A function can be called by adding parentheses to its name
For eg: fnName();

Function parameters and arguments 
Parameters are the names listed in the function definition Eg: function(a){return a*a};
Arguments are the values received by the function Eg: function(2)

Difference between Normal Fn and Arrow Fn

                                             
1. "this" Keyword : "this" refers to the object that is currently executing the function.

# Normal Fn
> Has its own "this"                                              
    For Eg: 

    --CODE--
    const obj = {                                              
        name: "Rojen",                                             
        hello() {                                               
            console.log("Hello" + " " + this.name);                       
        },                                                        
    };                                                            
    obj.hello();                                                 

    --OUTPUT--                                                   
    Hello Rojen        

? this = obj so, "this.name" is same as calling "obj.name"

# Arrow Fn
> Inherits "this" from surrounding scope: 
    For Eg:

    --CODE--
    const obj = {
        name: "Rojen",
        hello: () => {
            console.log("Hello" + " " + this.name);
        },
    };
    obj.hello();

    --OUTPUT--
    Hello undefined

? The arrow function ignores the object and checks the surrounding scope. So, since there is no global obj "this.name" returns undefined. This is called lexical binding 



2. "arguments" Object

# Normal Fn
> Normal function automatically gets an "arguments" object which stores all arguments passed to the function.
    For Eg:

    --CODE--
    function arg() {
        console.log(arguments);
    }
    arg(1, 2, 3);

    --OUTPUT--
    [1, 2, 3]

# Arrow Fn
> Arrow functions do not have "arguments" object. 
    For Eg:

    --CODE--
    const args = () => {
        console.log(arguments); 
    }
    args();

    --OUTPUT--
    ReferenceError: arguments is not defined



3. Constructor Functions

# Normal Fn 
> can use constructor functions
    For Eg:

    --CODE--
    function create (name) {
        this.name = name;
    }
    const obj = new create("Rojen");
    console.log(obj.name);

    --OUTPUT--
    Rojen

? The "new" keyword creates a new object then sets "this" to that object

# Arrow Fn
> cannot use constructor functions
    For Eg:

    --CODE--
    const create = (name) => {
        this.name = name;
    };
    const obj = new create("Rojen");

    --OUTPUT--
    TypeError: create is not a constructor

? Arrow functions cannot be constructors because they have no internal constructor behavior and no own this.



4. Hoisting
> Hoisting means JavaScript moves declarations to the top of their scope before execution.

# Normal Fn
> Normal Fns are fully Hoisted
    For Eg:

    --CODE--
    Hello();
    function Hello() {
        console.log("Hello");
    };

    --OUTPUT--
    Hello

? Even though the function is written later JS knows about it before execution begins.

# Arrow Fn
    For Eg:

    --CODE--
    Hello();
    const Hello = () => {
        console.log("Hello");
    };

    --OUTPUT--
    ReferenceError

? The variable sayHello exists but it cannot be used until the declaration is reached because it is in the Temporal Dead Zone (TDZ).

            ## Temporal Dead Zone (TDZ)
            >   The TDZ prevents you from accidentally using variables before they have been initialized helping catch bugs early.
                Let and Var have different behaviours in TDZ
                Let returns an error whereas var returns undefined which makes let better as it is better to get a error ranther than a random undefined which is difficult to debug     


5. Implicit Return

#Normal Fn
> Normal functions always need "return".
    For Eg:

    --CODE--
    function square(x) {
        return x * x;
    }
    square(2);

    --OUTPUT--
    4

# Arrow Fn
> Arrow functions can skip "return" if there is only one expression.
    For Eg:

    --CODE--
    const square = x => x * x;
    square(2);

    --OUTPUT--
    4
